# Windows guest runtime

`WindowsGuestRuntime` implements `GuestImportResolver` using the caller's `MappedGuestMemory`, `GuestCallbackTable`, CPU and `GuestCallRunner`. It never loads or executes a native library.

1. Map the PE with `mapPeImage` and create the callback table.
2. Construct `WindowsGuestRuntime({ memory, callbacks, capabilities })`.
3. Register additional known services with `register(library, name, signature, invoke)` before preparing the image.
4. Call `prepareImage(image)`. This binds import slots, assigns the static TLS index/template, registers image unwind records, and patches CFG pointers. Unknown function imports bind to named traps that throw `UnsupportedWindowsImport` when reached. The two imported MSVC locale identifier variables have writable guest storage.
5. Map a thread stack and return sentinel, create the shared CPU/runner, then call `attachRunner(runner)`. The CPU's host-call predicate must include all callback table addresses, including callbacks created during image preparation. FS/GS selects the guest TEB; stack bounds, thread identity, last error and TLS pointers reside in guest memory.
6. Call `initialize(image, { context, instructionBudget })`. TLS callbacks receive `(module, DLL_PROCESS_ATTACH, null)` before the CRT entry point. CRT initializer tables run through nested guest calls; the DLL's actual code initializes the security cookie and static objects.
7. Call `detach(image, options)` for process-detach notifications and CRT teardown. This sends notifications; the execution owner retains responsibility for unmapping the image and disposing of the process runtime.

File access uses the supplied synchronous `openFile` capability and guest handle records. Standard I/O, wall time, performance time, environment and command line have explicit capability inputs. The runtime does not read arbitrary host files or launch processes.

`coverage` reports requested/reached function imports, whether a service implementation exists, call counts, failure counts and the most recent failure. A supported service may reject an unsupported mode. Imported data is writable guest storage and does not count as a reached function call. A bound trap is not an implemented import.

The installed DLL tests complete process attach and detach for CTF i386, LMCTF i386 and rerelease x64. Rerelease initialization traverses its real CRT function tables, updates the guest TLS epoch and executes checked CFG dispatch. These tests read installed files under `~/Projects/qfiles/q2`; absent files are explicitly skipped. The classic API host's separate CTF test also reaches world spawning, a client connection, a frame, game/level save writes, a game save read and shutdown through this runtime. The rerelease host reaches PreInit and Init with the MSVC clock binding.

The x64 MSVC services initialize `ios_base`, `basic_ios`, `basic_ostream`, `basic_iostream` and `basic_streambuf` in guest memory. The DLL retains its compiled stringbuf constructors, growth, seeking, high-water state and destruction. Imported buffer operations dispatch through the guest vftable; numeric insertion honors the C locale, base/sign flags, fill and width. Locale implementation and facet reference counts, `_Locinfo` yarn storage and recursive library locks also use guest bytes. Unknown locale names, custom numeric facets, standard-stream ownership and stream exceptions fail explicitly.

`bun test tests/guest/runtime/windows/msvc.test.ts` constructs actual retail stringstream/ostringstream objects, grows and reads buffers, formats signed and hexadecimal integers, seeks, copies between streams, and executes both most-derived destructors. It pins the DLL digest because the internal constructor addresses are specific to that artifact. The separate `Q2_RR_SPAWN_PROBE=1 bun test tests/compat/q2/rerelease/native.test.ts -t PreInit` continuation passed the reached streams and stopped at the engine's unbound `game.trace`; entity spawning is not yet qualified by this runtime check.

This is a single-thread runtime. Recursive critical sections and uncontended SRW locks work; contended locks and waits need a guest scheduler. C++ exception dispatch/unwinding, populated type-name destruction lists, other MSVC stream/locale modes, CRT formatting/scanning, and several unreached imports remain explicit traps. `RtlLookupFunctionEntry` resolves the registered PE runtime-function table; `RtlVirtualUnwind` is not implemented. No map/frame/save qualification is inferred from DLL initialization.
