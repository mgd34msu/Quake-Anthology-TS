# System V guest runtime

`SystemVGuestRuntime` implements `GuestImportResolver` over the caller's `MappedGuestMemory` and `GuestCallbackTable`. Attach the existing `GuestCallRunner` before execution. The CPU's host-call predicate must recognize that callback table's addresses. Linux and Windows runtime instances belong to separate guest processes; neither creates a second CPU or memory namespace.

```ts
const runtime = new SystemVGuestRuntime({ memory, callbacks, argv, environment, capabilities });
runtime.attachRunner(runner);
const image = runtime.load({ bytes, module, loadBias });
runtime.initialize(image, { context, instructionBudget: 20000 });
```

`load` uses the shared ELF loader, the process's GNU-unique registry, exact symbol versions, dependency names, TLS bindings, and symbol sizes. Registered guest images can supply versioned exports. Missing weak imports stay null. Supported service addresses are real guest callback traps. Unavailable function versions raise `UnsupportedSystemVService` when called. Unsupported RTTI data receives an explicitly labeled inaccessible guest reservation. Relocation temporarily validates its address while no guest instructions execute; it is inaccessible before execution. This records missing data without fabricating a vtable or a type descriptor. COPY relocations cannot use such a reservation because its provider size is unknown.

The runtime installs one thread's FS/GS base, TCB self pointers, DTV, errno, and aligned static TLS blocks. Relocated template bytes and zero fill live in guest memory. ELF TLS module IDs and offsets refer to those blocks. The x64 `__tls_get_addr` service reads the guest DTV. The static TLS reservation is 64 KiB with at most 1,024 modules. Dynamic thread creation and i386 GNU `___tls_get_addr` register-parameter entry are unsupported. IFUNC execution is also unsupported by this runtime loader wrapper; the underlying ELF loader requires an explicit guest resolver for it.

`initialize` runs executable preinitializers, dependency initializers, DT_INIT, then DT_INIT_ARRAY. `finalize` follows the ELF loader's reversed DT_FINI_ARRAY and DT_FINI ordering. Completed calls appear in `lifecycleTrace`. Each guest entry has the supplied instruction budget; nested entries debit the active runner budget. Failed initialization preserves the faulting CPU state and cannot silently restart. Registered `__cxa_atexit` callbacks run once in reverse registration order, filtered by DSO, through the same runner. A finalizer's own `__cxa_finalize` call controls its registered destructors.

Implemented services cover guest allocation/free/reallocation, memory and byte-string operations, fortified copy bounds, integer conversion, qsort with nested guest comparators, deterministic injected time, scalar math, C++ allocation, local-static guards, exception storage allocation, destructor registration, and standard-stream initialization and flushing. Storage remains guest bytes. Math services use JavaScript's numeric functions at the ABI boundary; exact glibc last-bit, errno, and floating-environment parity is unverified. C++ exception storage allocation does not imply personality dispatch or unwinding support. Process allocator/destructor/image metadata is runtime-owned; checkpointing an entire runtime instance is not implemented.

`ios_base::Init` constructs eight narrow/wide standard streams and six synchronized FILE buffers. Their GCC 4.8 i386/x64 layouts, virtual-base offsets, RTTI pointers, stream-buffer virtual entries, classic locale facets and caches, ties, `unitbuf`, reference counts, and FILE fields live in guest memory. Further Init instances retain the existing streams. The final Init destructor flushes output streams in source order and leaves the permanent reference. `runtime.iostreams` exposes their addresses; `systemVIosLayout` and `systemVFileLayout` expose the byte layouts.

Standard I/O uses optional injected capabilities: `standardInput(maximumBytes)` returns bytes, `standardOutput(stream, bytes)` returns the count written, and `standardFlush(stream)` returns zero on success. `outputIsTerminal` enables stdout line buffering. C `fgetc`, `fputc`, `fread`, `fwrite`, `ungetc`, `fwide`, and `fflush` share FILE bytes with C++ stream buffers. Missing input or pending-output capabilities stop explicitly; flushing an empty stream needs no output capability. Narrow bytes and wide ASCII conversion follow the classic C locale. The supported stream-buffer virtual calls perform actual guest-byte transfers and nested calls through the shared guest runner.

The supplied Quake Live `qagamei386.so` and `qagamex64.so` each produce 105 import relocation occurrences and seven initializers. Both now execute all seven initializers and all ELF finalizers through the shared CPUs. Each module calls Init four times, leaving reference count five after initialization and one after finalization. No unsupported service is reached during these calls. Quake Live is an additional compatibility fixture, not an official Quake III product; this establishes module initialization and teardown, not gameplay.

Old-ABI libstdc++ string/tree operations, numeric formatting/parsing facets, named locales, general libc locale internals, FILE seek/open and most FILE virtual operations, stream/facet destruction outside Init, and C++ exception propagation remain unsupported. Unimplemented C++ virtual methods contain explicit unavailable callbacks. The classic locale's C classification tables and stream-required facet data are present; they do not establish arbitrary `locale_t` compatibility or complete facet behavior. Unrelated imported RTTI, including `runtime_error`, can still be unavailable. The runtime does not load a native C/C++ library.

Service providers register functions with `service(library, name, versions, parameters, result, invoke)`, publish guest storage with `data(library, name, version, address, byteLength)`, and obtain bindings through `resolveAddress(library, name, version)`. `unavailable(library, name, parameters, result, detail)` creates a guest callback that records and throws the unsupported boundary. All service arguments/results use the existing typed guest ABI.

Run `bun test tests/guest/runtime/system-v` for authored ELF32/ELF64 initialization and finalization, static TLS, nested guest comparators, guards, destructor ordering, guest stream/facet virtual calls, and the supplied modules. `bun tests/guest/runtime/system-v/fixtures.ts` prints source hashes and required dynamic symbol metadata without writing commercial bytes to disk.
