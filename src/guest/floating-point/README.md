# Guest floating point

`executeNumericInstruction({ state, memory, instruction })` consumes a decoded legacy x87/SSE instruction. The CPU supplies resolved memory addresses, ModRM register indices, mandatory prefix, operand width, and immediate. The handler returns `executed`, `unsupported`, or a processor `exception`; the CPU owns instruction-pointer advancement and memory faults. It operates directly on `GuestProcessorState.x87` and `.simd`.

`binary.ts` computes with BigInt significands, integer exponents, and exact quotient/remainder rounding. Binary32, binary64, and the 64-bit significand of binary80 have separate formats. Division and square root do not pass through JavaScript floating-point arithmetic. Four rounding modes, subnormal values, payload-bearing NaNs, infinities, and signed zero remain explicit. `readX87Return` and `writeX87Return` convert JavaScript numbers only at the ABI boundary through raw binary32/binary64 bytes.

The x87 executor handles real/integer loads and stores, register transfers, stack tags/TOP, arithmetic and reverse/pop variants, comparisons and conditional moves, sign/absolute value, zero/one constants, square root, integral rounding, control/status words, environment save/restore, initialization, and deferred exceptions. Unmasked register overflow/underflow uses the architectural 24576 exponent adjustment. Unmasked store overflow/underflow preserves the destination and stack; invalid/denormal/divide-by-zero faults are deferred until a waiting instruction. Raw80 load/store and register transfers preserve noncanonical encodings.

The SSE executor handles legacy scalar/packed moves, aligned-access faults, binary32/binary64 arithmetic and square root, min/max, comparisons, masks, integer/float conversions, shuffles/unpacks, bitwise operations, selected packed integer arithmetic/multiplication/comparisons/shifts, and MXCSR load/store. Packed results are computed before writing destination lanes, so an unmasked SIMD exception leaves the destination unchanged. MXCSR supplies rounding, exception flags/masks, DAZ, and FTZ.

Unsupported encodings return an explicit stop. Current gaps include x87 transcendental/remainder/scale/extract operations, nontrivial x87 constant loads, packed BCD, MMX, FXSAVE/FXRSTOR, approximate reciprocal/reciprocal-square-root instructions, packed saturation/min/max/averages, SSE3 horizontal arithmetic, SSE4, VEX/AVX, and EVEX. These gaps prevent a claim of complete native-module coverage. Architecture-selected transcendental and approximate-instruction results need separate implementations; they are not replaced by `Math` approximations.

The instruction rules follow the [Intel SDM](https://www.intel.com/content/dam/www/public/us/en/documents/manuals/64-ia-32-architectures-software-developer-vol-1-manual.pdf), especially chapters 4, 8, 10, and 11 and appendix E. The compact tests in `tests/guest/floating-point` include exact rounding/exception boundaries and a SHA-pinned original LMCTF `VectorLength` routine executed through the PE loader and i386 CPU. Its `(2^30, 1, 1)` vector returns raw80 `401d8000000000000008`, retaining contributions a binary64 accumulator loses. Existing x64 tests execute the retail rerelease DLL's `GetGameAPI` import-table copy through the shared SSE move implementation.
