# Quake Anthology 1.2.0

Performance release for the shared TypeScript engine for Quake, Quake II,
Quake III, their expansions, and supported rerelease content. Every change in
this release is behavior-preserving: rendered output and gameplay are
bit-identical to 1.1.10, verified against the full test suite (including the
pixel-exact render tests) and, for the dynamic-light change, against the
previous formula over 400,000 boundary-focused cases.

## What's faster

- **Model pose interpolation is cached.** MD2 and MDL frame interpolation is a
  pure function of its inputs, and the same pose repeats across entities and
  shadow passes every frame. Interpolated poses are now cached per model
  instead of recomputed per entity per pass.
- **Quake II fragment lighting is allocation-free and skips provable zeros.**
  Dynamic-light contributions and fragment shading write into scratch values
  instead of allocating per light per fragment. Lights are culled per
  triangle by exact AABB reach, and a fragment's contribution now skips the
  distance/division work entirely when falloff or the Lambert term is
  provably zero — the guard margins dwarf the full computation's rounding, so
  skipped fragments are exactly the zeros the full path produces. A profiled
  Quake II rerelease frame issued ~1.7 million `Math.hypot` calls; dynamic
  lighting accounted for 82% of them.
- **Depth-only passes skip all color terms on the CPU renderer.** Shadow
  atlas casters and shadow volumes no longer evaluate texturing, lighting,
  or fog; they write depth only (including for fragments that write no
  color, which previously skipped depth as well).
- **The CPU shadow atlas target is reused.** Each shadow rebuild allocated a
  fresh 2048×2048 software renderer — tens of MB of framebuffers — and copied
  the whole depth image in and out. The target renderer is now reused across
  operations and depth copies cover only the pass rectangles.
- **BSP visibility traversal allocates nothing per node.** The pending stack
  is flat numeric arrays with the same push/pop order (so surface order is
  unchanged), replacing one object per visited node per frame.
- **GL shadow draws validate once.** Retained depth-atlas draws are
  immutable by identity; their positions and indices are validated on first
  use instead of on every shadow update.

## Measured

640×480, `tools/profile-frame.ts`, median frame time on a contended machine
(absolute numbers vary; deltas are the signal):

- Quake II rerelease, GL renderer: ~78 ms → ~65 ms
- Quake classic, CPU renderer: ~147 ms → ~136 ms
- Quake II rerelease, CPU renderer: ~536 ms → ~506 ms

Simulation was never the bottleneck (~0.75 ms Quake classic, ~2.8 ms Quake II
rerelease); presentation and rasterization were, and remain the focus of
further performance work. The CPU renderer is still far slower than GL on
shadow-heavy rerelease scenes — GL stays the default.

## Fixed

- CPU depth-only fragments (shadow volumes, atlas casters) with color writes
  disabled now still write depth.
