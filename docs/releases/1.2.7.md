# Quake Anthology 1.2.7

Stock games now behave like the originals on disk. A game made entirely from one product or mod
reads and writes its own config file, keeps demos, screenshots, logs and saves in its own
folders under the original names, and Quake II saves in the original classic and rerelease
formats, so saves move between this engine and the original games in both directions. The
engine keeps one configuration that every game starts from, binds included, and every classic
cvar name works in every game. This release also hardens the handling of untrusted network and
game-module input, and removes caps that limited legitimate content or performance.

## Added
- `--vm-game 0` runs a mod's native Quake III `qagame` module (Windows `.dll` or Linux `.so`) as
  the server game instead of its bytecode, falling back to `vm/qagame.qvm` when the mod ships
  none. Native module state, heap and fiber-local storage are saved with the game.
- `--lan-only` makes NetQuake and Quake II KEX LAN hosts ignore every datagram from a
  non-private address.
- `--allow-load-paths` lets scripts, game modules and remote clients `load` a save from outside
  the save directory.
- `cl_http_package_downloads` (default 1) turns off HTTP package downloads (`pak`, `pkz`, `pk3`)
  while keeping other downloads.
- Quake II native downloads that are interrupted resume from a `.part` file once its length and
  SHA-256 still match.
- Quake Live table-style game modules expose their full export table.
- Stock games (every component from one product or mod) read and write their own config file
  where the original keeps it: `config.cfg`, `q3config.cfg`, or the rerelease `kexengine.cfg`,
  `system.cfg`, `settings.cfg` and `keybinds.cfg` under Saved Games.
- Settings layering: the engine's own configuration is the default for every game, binds
  included, and feeds each stock game's config file. Changes made in game, typed in the console
  or run from scripts go to the engine level; a hand-edit of a game's file, or `bind -local`,
  `unbind -local` and `set -local`, keeps a value for that game only. The binding menus have a
  "Keep bindings to this game" toggle.
- Every classic cvar spelling works in every game (`vid_gamma`, `s_volume`, `cg_fov`,
  `cl_sensitivity`, `gl_mode` and the rest), as an alias of the engine's own cvar.
- Stock games write demos, screenshots, level shots, logs, `listip.cfg` and saves in their own
  game folders with the original names. Earlier demos and saves are moved there on first launch.
- Stock Quake II saves and loads in the original formats: classic `save/NAME/` folders
  (`server.ssv`, `game.ssv`, `MAP.sav`, `MAP.sv2`, autosave `save0`) and rerelease
  `NAME.pak.gz`. Saves written by the original games load, and rerelease saves with player and
  level state now restore in full.
- `qconsole.log` for every game from one writer: `logfile` in Quake II and III, `-condebug` in
  Quake and QuakeWorld.

## Changed
- Security limits on untrusted input:
  - Servers cap connections per address, gate connectionless-packet floods, expire challenges
    after 30 seconds, bound decompression, and back off after repeated wrong rcon passwords.
  - Server-supplied downloads are limited to asset types, and HTTP download servers on
    private hosts are refused unless the game server is private too.
  - Quake II game modules can run only a short list of console commands, and cannot write to
    executable, package or startup-config names.
  - `llm_exec` rejects more commands (quit, connect, map changes, chat, file writes and similar)
    and cvars whose values run as commands.
  - `load` of a file outside the save directory is accepted only from the local console.
  - LLM credentials move to `~/.local/share/quake-typescript/settings/` with mode 0600, and the
    crash log is mode 0600 with passwords and tokens redacted.
- A fault caused by one network peer drops that peer; a frame fault restarts the map on a
  dedicated server or returns a graphical client to the menu; a dedicated server exits after
  repeated faults.
- Quake III ladder climbing stays on by default; `pmove_ladders 0` disables it.
- The Quake III server runs its first-admission settle frames, so the first user commands carry
  real elapsed time.
- Downloads go to the game folder of the game they belong to; a read-only install falls back to
  the engine's own folder, which is still read.
- Removed caps that limited legitimate content or performance: guest mapped memory (1 GiB) and
  single `TagMalloc` (256 MiB), image dimensions, QVM data size, the Quake II HUD picture count,
  the saved server list, guest file-write quotas, mixer voices, ZIP member size, TrueType glyph
  and atlas sizes, per-byte guest `memcpy`/`memset` charging, and the HTTP download size limits.
  Leak guards, cache bounds, crafted-file guards and runaway guards stay.

## Fixed
- Unified input: movement provider bounds are enforced at the input boundary.
- Legacy translucent world surfaces draw after opaque entities.
- HTTP downloads accept decoded gzip bodies, and compare length only for identity encoding.
- Quake pushers touch triggers before impact.
- Rerelease Quake II `BoxEdicts` filters may link or unlink entities. Monsters that dodge from
  inside `M_CheckDodge` previously ended the run with "Q2 BoxEdicts filter cannot modify world
  links".
- No old world survives a map change, in graphical or headless runs.
- A secondary Quake II seat waits for the primary seat's world before loading, so it no longer
  captures stale content or fails to rebind after map travel.
- Restored Quake II trains keep their wait.
- Native game profiles for the 1998 Xatrix (The Reckoning) release, and rerelease Gekk water
  movement.
- A program in a product's user content folder now satisfies its required programs (for example a
  user `qwprogs.dat` beside an installed mod).
- Saved bindings are no longer overwritten by the menu's Play, and the menu reloads bindings when
  the product changes.
- Map changes load the new world's archives.
- Dedicated servers read and save their archived settings.
- Global tuning applies on direct launches.
- Loading a Quake II save written by the original game no longer faults on the saving process's
  client pointer.
- Starting a Team Arena skirmish from a Quake III world loads the Team Arena archive.
- The first game's config file seeds the engine-level bindings only with bindings the player
  changed, so one game's stock bindings (Quake II's `7` = `use Rocket Launcher`) no longer
  become every game's.

## Performance
- Guest write observers are indexed by backing page.
- Merged render geometry is retained by constituent identity.
- PVS-invisible BSP subtrees are skipped through ancestor marks.
