# SRC8B remediation
| ID | status | note |
|---|---|---|
| SRC8B-001 | fixed | botNavigationProfile grants teleport and jump-pad for Q3 movement. Live check on retail q3dm17 (six skill-3 bots, 90 s): 13 teleports (health continuous, arrival at the teleporter exit) and jump pads selected 24 times with 478 pad move commands; on q3dm19 jump pads were selected 6 times. Control before the change: 0 pad or teleporter routes. Tests: tests/bots/navigation/q3-routing.test.ts and aas-routing.test.ts.
| SRC8B-002 | fixed | maximumDrop no longer applies to AAS edges (it still limits constructed and NAV graphs). Tests: aas-routing.test.ts and q3-routing.test.ts (falls over 128 on q3dm17). |
| SRC8B-003 | fixed | bestReachableFromJumpPadArea is now AAS_BestReachableFromJumpPadArea: it walks the map's trigger_push entities (SourceBotNavigationHost gains `bspEntities`, threaded from the director, and `modelBounds`, which the guest answers from the collision model), derives the launch point and velocity as AAS_GetJumpPadInfo does (target origin, gravity from the move state, the 1.1 factor), keeps pads overlapping a jump-pad area, flies the box with a new SE_HITBOUNDINGBOX prediction (30 frames, 0.1 s) and returns the largest pad area of the first pad that hits. Area ranking uses the node box volume because the loaded graph has no faces for AAS_AreaVolume. Test: tests/bots/navigation/q3-routing.test.ts (q3dm17 mega health now reachable from a pad area; a far box is not); previously 0. |
| SRC8B-004 | fixed | For AAS edges the static test checks only the entered area (plus the per-query disabled set), so a bot in a disabled area can leave it. Test: aas-routing.test.ts. |
| SRC8B-005 | fixed | Fallback box is expanded by the crouch hull (earlier); now the drop uses aasTraceClientBBox, the AAS area-tree walk moved from the authoring-only AasReachabilitySpatial into aas.ts (the runtime asset does have nodes, planes and settings, which is all it reads), so linked movers no longer affect it; graphs with no AAS asset keep the BSP trace. Test: tests/bots/navigation/aas-client-trace.test.ts (retail q3dm1.aas). |
| SRC8B-006 | fixed | Alternative-route goals and AAS_AreaInfo report the AAS area center. No test. |
| SRC8B-007 | fixed | Equal areas return 1 before the range checks, in the estimator and in SourceBotNavigation. Tests: tests/bots/navigation/estimates.test.ts (expectations changed: it asserted (0,0) unreachable) and aas-routing.test.ts. |
| SRC8B-008 | fixed | Prediction events now follow be_aas_move.c: SE_HITGROUND and SE_LEAVEGROUND report the current ground state each frame instead of a change, SE_GAP (64) runs the source probe (crouch box 48 + phys_maxbarrier below the origin, a gap if the floor is more than phys_maxstep + 1 lower and not water) and SE_HITBOUNDINGBOX (2048) is raised for a `hitBox` supplied on the query (bot-prediction.ts). The botlib export passes no box, so a QVM syscall 318 request for 2048 still never fires, as in id; the box is used by the jump-pad item test (SRC8B-003). Tests: tests/bots/navigation (59 pass, includes aas-reachability authoring that uses these events) and q3-routing; no dedicated SE_GAP test. |
| SRC8B-009 | fixed | Syscall 308 clamps a negative area limit to 0; AAS estimate distances that are non-finite or out of int range convert to the source clamp (1) and a non-finite origin no longer throws for AAS. Test: estimates.test.ts (the old throw expectation was changed). |
| SRC8B-010 | fixed | An oversized integer epair saturates at int32 in both decimalInteger copies instead of throwing. No test. |
