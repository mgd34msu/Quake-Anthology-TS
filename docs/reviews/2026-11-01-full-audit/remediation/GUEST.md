# GUEST remediation

| ID | status | note |
| --- | --- | --- |
| GUEST-001 | no-action | Info. The documented boundary is narrowed by the fixes below (GUEST-002, 006, 007, 009); no code change. |
| GUEST-002 | fixed | `AddCommandString` now passes through `filterGuestConsole` (`src/compat/q2/guest-console.ts`) in the classic and rerelease hosts: only `map gamemap kick say echo exec wait` run, others (quit, set*, rcon, bind, alias) are dropped with a debug print. Earlier: private cvars hidden and write-protected. Test: `tests/compat/q2/guest-console.test.ts`. The separate `game-module` command origin was not added; the allowlist is the boundary. |
| GUEST-003 | fixed | `argv`/`args` strings are released when a different command is read (`CommandGuestStrings`), and cvar value strings are rewritten in place per record (`ReusableGuestString`) in both the classic and rerelease hosts. Test: `tests/compat/q2/guest-strings.test.ts`. |
| GUEST-004 | fixed | New number-based predecoded i386 executor (`src/guest/x86/fast.ts`) used by `I386Cpu` for the common integer, string, branch and x87 instructions (generic path remains for the rest and for non-flat segments or non-pristine state); `SparseGuestMemory.scalarRead/scalarWrite` avoid GuestAddress allocation; `I386Cpu` takes `callbacks` so unhooked instructions skip the host-call hook. Measured on retail gamex86.dll (host load 6-8, so ratios matter): ctf attach+detach 0.45-0.62 to 1.58-1.90 MIPS; real ctf server frames (26,690 instructions each) median 57.8 ms to 16.0 ms; load of base1 2.0x to 4x. Instruction counts are identical before and after (300326, 308335, 1601403, 48573). Tests: `tests/guest/x86/fast.test.ts` (22,000 random single instructions and sequences compared with the generic path, REP semantics, code invalidation, fault atomicity, retail ctf and xatrix attach/detach bit-identical in registers, flags and memory digest), plus existing guest, x86, x64, abi, windows and classic suites (168 + 25 pass). |
| GUEST-005 | fixed | `fast-arithmetic.ts` adds an allocation-free exact fast path: SSE binary32 and binary64 add/sub/mul/div (scalar and packed) and x87 `D8/DC/DE` register and memory forms in round-to-nearest, using doubles plus the Dekker/Knuth error term for the inexact flag and the C1 round-up bit. x87 precision control 53 and 24 round like the host double (24 only for binary32 operands) and precision 64 is taken only when the result is exact; NaN, infinity, subnormal, out-of-window, directed rounding and unmasked precision exceptions fall back to the rational path before any state changes. `fastBinary32` no longer allocates per call. Tests: `tests/guest/floating-point/fast-arithmetic.test.ts` (x87 for every precision control and 6 operations, SSE binary64 scalar and packed, compared with the exact path), existing `sse-fast-path.test.ts`. |
| GUEST-006 | fixed | `GuestCallRunner.chargeBytes` charges one budget unit per 64 bytes; the Windows CRT `memcpy`, `memmove`, `memset`, `memcmp`, `memchr`, `strlen`, `strcmp`, `malloc` and `calloc` services call it. Test: `tests/guest/abi/runner-inline.test.ts` (charge exhausts the budget). |
| GUEST-007 | fixed | `SparseGuestMemory` takes `maximumMappedBytes` (default 1 GiB) and raises `GuestMemoryFault("quota")` past it; classic `TagMalloc` is capped at 256 MiB like the others. Test: `tests/guest/core/memory.test.ts`. |
| GUEST-009 | fixed | `classicGuestFiles` refuses writes to `.cfg .rc .dll .so .exe .pak .pk3 .qvm .bsp` and similar names (the guest sees a missing file), caps a file at 64 MiB, session growth at 512 MiB and written files at 256 (short writes beyond). Test: `tests/compat/q2/classic/services.test.ts`. |
| GUEST-010 | fixed | Unsupported or stray conversions print literally; `h`, `hh`, `ll`, `I64`, `I32`, `j`, `z`, `t`, `L`, `w` modifiers are parsed and 64-bit integers use an int64 variadic layout. The existing test asserted the throw for `%I64d`; it now asserts the new behavior. Test: `tests/compat/q2/classic/host.test.ts`. |
| GUEST-011 | fixed | `SparseGuestMemory.writeDeliveries` counts stores that reached an observer; the integer block kernel leaves the block only after a delivered store instead of after every unsafe step while any observer exists. The register checkpoint per unsafe step is still taken. No new test; covered by the existing x64 tests. |
| GUEST-012 | fixed | Classic cvar refresh and edict records were incremental earlier. The rerelease `reconcile` now decides unchanged slots with one number-addressed `scalarRead` of `inuse` against the retained lifetime (no `RawEntityView`, `GuestAddress` or `borrow` per slot), and only slots whose binding may have changed, or that a foreign projection or restore engages (`RereleaseForeignActors.engaged`), go through `actor()`. Covered by the existing `tests/compat/q2/rerelease` suite; no dedicated test. |
| GUEST-013 | fixed | `SparseGuestMemory.allocate({ pooled: true })` serves one-page allocations from 64-page slabs (no mapping, typed array or splice per allocation); an exact one-page `unmap` zeroes and reuses the page. Only engine-owned reusable and command strings (`guest-strings.ts`) opt in; guest heap, TagMalloc and API string blocks stay individually mapped because six existing tests assert page-tail and use-after-free faults for them. `clientThink` keeps one command record per nesting depth instead of a mapping per command, and CRT `strcmp` compares through retained scratch buffers. Tests: `tests/guest/core/memory.test.ts` (slab, reuse, zero on reuse, partial and double release); `tests/compat/q2/guest-strings.test.ts` now expects one slab instead of one page. |
| GUEST-014 | fixed | The x64 and i386 decode caches now hold 262,144 entries (sized for the 2.8 MB gamex64 image) and count every discard in `decodeCacheClears`, so a session can report recurring clears. The duplicated cache admission in `#runGeneric`/`#runManaged` is one `#admit`. Test: `tests/guest/x64/differential.test.ts` (cache is cleared once at the limit, counted, and execution continues correctly). A retail frame run to read the counter was not possible here. |
| GUEST-015 | fixed | x64 no longer advertises CMPXCHG8B, `0F 77` (EMMS) no longer consumes a ModRM byte on x64, and i386 gains `0F A2` CPUID through a shared `virtualCpuid`. Test: `tests/guest/x86/cpu.test.ts`. |
| GUEST-016 | fixed | `D9 F0 F1 F2 F4 F5 F8 F9 FB FD` (F2XM1, FYL2X, FPTAN, FXTRACT, FPREM1, FPREM, FYL2XP1, FSINCOS, FSCALE) are implemented with exact rational and fixed-point arithmetic in `x87-extended.ts`.
