# VM remediation

| ID | status | note |
| --- | --- | --- |
| VM-001 | fixed | Released foreign QC projection slots are queued and reused (after 64 later releases, so stale references see them free for a while) instead of burning a new edict each time. No test: provider tests need an installed Copper `progs.dat`. |
| VM-002 | fixed | Reads of an edict with no live actor return its last words, as `ED_Free` leaves most fields, instead of throwing; writes still require a live actor. Foreign slots keep their words on release and are zeroed on reuse. No test, for the reason above. |
| VM-003 | fixed | Each root QVM invocation has a 100,000,000 instruction budget and the compiled-profile return stack is capped at 65,536 calls; both raise `CommonError("drop")`. Test: `tests/compat/qvm/runaway.test.ts`. |
| VM-005 | fixed | Guest writes to `.pk3 .qvm .dll .so .dylib`, `q3key`, `q3config.cfg` and `autoexec.cfg` fail with ioquake3's "not a mutable name" warning. A protected-cvar flag was not added. Test: `tests/compat/qvm/client-file.test.ts`. |
| VM-006 | fixed | `$modlist` returns an empty list. The old test asserted the rejection; it now asserts the empty list through the trap. Test: `tests/compat/qvm/client-file.test.ts`. |
| VM-007 | fixed | OP_RETURN reads words past the end of the globals as zero. Test: `tests/compat/qc/memory.test.ts`. |
| VM-008 | fixed | Shift counts are masked to five bits. Test: `tests/compat/qvm/operations-shift.test.ts`. |
| VM-009 | fixed | An engine string that outgrows its buffer moves to a larger one; lookup is by map; `qw-name` is truncated to 31 characters. Test: `tests/compat/qc/memory.test.ts`. |
| VM-010 | fixed | Weapon-behavior target strings are interned (`QcStrings.intern`) instead of appended on every refresh. Test: `tests/compat/qc/memory.test.ts`. |
| VM-011 | fixed | Per-syscall cost: observation baselines are retained per frame and refreshed in place (`observe(into)`, no `slice` per field), pure query traps (trace, point contents, entities in box, contact, PVS, area connectivity, clock, cvar integer) skip the projected-field refresh and re-observation since they cannot change engine state, `actorAt` uses the slot index (earlier), and `QvmModPlayerEvents.publish` reads the three event words with `loadI32LE` and decodes the player state only when they changed. Existing `tests/compat/qvm` mod suites; not re-measured. |
| VM-012 | fixed | Message buffers are dropped before routing and bad messages are reported (earlier); the buffer is now flushed when the frame ends (`QcModProvider.advance`, which runs at frame exit) and at checkpoint, not after each top-level callback, so a message split across two callbacks is whole. All of `tests/compat/qc` (86 tests) passes unchanged; no new test for the split-message case. |
| VM-013 | fixed | Split out of the QVM provider (1414 to 1123 lines): `mod-fields.ts`, `mod-validation.ts`, `mod-checkpoint.ts`, `mod-projections.ts` and `mod-spatial.ts` (trace, contents, box and contact handlers). Checkpoint validation and restore share one decoder (`decodeQvmModHostState`), `validateQcMod` moved to `qc/mod-validation.ts`, and the callback-input table both validators repeated is one `modCallbackInputs`. The constructors still wire their subsystems inline. Covered by `tests/compat/qvm` and `tests/compat/qc` (passing). |
| VM-014 | fixed | `QvmMemoryWrites` keeps a 4 KiB page index of watched ranges, so stores elsewhere skip the watch scan. Covered by `tests/compat/qvm/committed-stores.test.ts`; not re-measured. |
| VM-015 | fixed | The resolver receives a lazy `words` accessor and the actor-semantics resolver exits early without actors and reads the first argument directly, so the per-call view and instruction lookup are built only on a candidate match. Not re-measured. Covered by `tests/compat/qvm/function-hooks.test.ts`. |
| VM-016 | fixed | Word-to-binding set (earlier) plus QC `find` now caches the string-field name per offset instead of scanning `program.fields` on each call. The `prepareEntities` scan remains because it carries liveness semantics. Test: existing `tests/compat/qc/runtime.test.ts`, `rerelease-builtins.test.ts` pass. |
| VM-017 | fixed | `memcpy` with identical pointers is a no-op, and overlapping `memcpy` and `strncpy` behave as memmove. The test that asserted the rejection now asserts the copy. Test: `tests/compat/qvm/committed-stores.test.ts`. |
| VM-018 | fixed | QVM data is capped at 64 MiB (retail modules need a few MiB), with an error naming the hunk allocation. Test: `tests/compat/qvm/runaway.test.ts`. |
| VM-019 | fixed | Guarded QVM `close()` (earlier) and QC restore now validates and decodes the checkpoint before `closeClientBindings` (`preflightQcCheckpoint`, `QcMachine.validateSnapshot`), so a corrupt save fails with nothing released. Test: `tests/compat/qc/checkpoint-components.test.ts` and mod-provider tests pass; no new negative test. |
| VM-020 | fixed | The interpreted mode is now deliberate: `vm_game`, `vm_cgame` and `vm_ui` (id's cvars, default 2) select it, `1` runs vm_interpreted.c semantics and anything else the compiled semantics id ships; `QvmModuleOptions.semantics` carries it, the numeric profile is renamed `q3:qvm-binary32` (nothing persisted the old id), and `vmlist` prints the real mode. Test: `tests/compat/qvm/runaway.test.ts` (cvar mapping). |
| VM-021 | fixed | Tests added for the instruction budget and call depth, shift masking, memcpy overlap, `$modlist`, immutable names, the QVM data cap and QC string growth. Not covered: foreign-slot churn and stale reads (see VM-001, VM-002). |
