# BOTS remediation
| ID | status | note |

| BOTS-004 | fixed | Pacing of failed plans (earlier) plus: a path is replanned for a moved goal by comparing against the goal it was planned for, not its end (a path ends at the nearest node, so an off-graph goal replanned every frame); the replan interval is spread by bot id (2.0-2.75 s) so bots do not plan together; node hazard contents are memoised per navigation graph for the brain's life instead of per plan. Measured on base1 (retail Q2 rerelease nav.), 8 bots, 200 frames, unplannable combat goals: 0.63-1.6 ms/frame with the per-plan hazard memo against 0.20-0.74 with the per-graph one over three runs on a loaded machine (22030 vs 10382 pointContents calls; the "before" arm rebuilds the node list each call to defeat the cache, and already includes the earlier failed-plan pacing); 36 plans in 1600 thinks. Tests: tests/bots/behavior/rerelease/replan-cost.test.ts (prints the figures), replan.test.ts. |
| BOTS-005 | fixed | Runtimes over one graph share estimate caches when their eligibility scope matches (capabilities, team, monster, max drop, blocked edges, disabled areas); tails and AAS caches live in a shared store keyed by the edge list, with the entry and 16 MB budgets applying to the shared store, and the incoming-edge maps are built once per graph. Tests: tests/bots/navigation/estimate-sharing.test.ts, estimates.test.ts. |
